# Tracechain-rust

این پروژه بازنویسی آموزشی مدل زنجیره بلوکی و ران‌تایم Go/Cosmos ما در زبان **Rust** است. هدف اصلی این پروژه یادگیری سینتکس و مفاهیم زبان **Rust** از طریق شبیه‌سازی یک سیستم شبیه به **Polkadot** یا **Substrate-inspired** به صورت ساده و قابل فهم است.

> **نکته بسیار مهم:** این پروژه یک پروژه واقعی Polkadot SDK یا FRAME نیست. در این پروژه از هیچ کتابخانه خارجی (مانند `Substrate` یا `serde` یا `tokio`) استفاده نشده و تنها از کتابخانه استاندارد Rust (نسخه پایدار Rust 2021) استفاده گردیده است. هدف آن ایجاد یک پل ذهنی از مفاهیم Go/Cosmos به مفاهیم Rust/Substrate است.

---

## ۱. مقایسه مفاهیم (Core Mapping)

ما مفاهیم پروژه Go/Cosmos را به اصطلاحات الهام‌گرفته از Polkadot/Substrate در Rust نگاشت کرده‌ایم:

| Go / Cosmos model | Rust / Polkadot-inspired model | توضیحات |
| :--- | :--- | :--- |
| `Tx` | `Transaction` | تراکنش حاوی امضا، nonce و چندین فراخوانی |
| `Message` | `RuntimeCall` | فراخوانی‌های داخل یک ران‌تایم که به صورت enum پیاده‌سازی شده‌اند |
| `MsgDeposit` | `RuntimeCall::Deposit` | واریز وجه به صندوق |
| `MsgWithdraw` | `RuntimeCall::Withdraw` | برداشت وجه از صندوق با سوزاندن سهم‌ها |
| `Signer` | `signer` | امضاکننده تراکنش |
| `Sequence` | `nonce` | مقدار nonce برای جلوگیری از حملات Replay |
| `AnteHandler` | `TransactionValidator` | اعتبارسنجی اولیه تراکنش |
| `BaseApp` | `Runtime` | هسته اصلی ران‌تایم زنجیره بلوکی |
| `BankState` | `BankState` | وضعیت موجودی حساب‌ها |
| `VaultState` | `VaultState` | وضعیت سهام و موجودی صندوق |
| `AccountState` | `AccountState` | وضعیت nonce حساب‌ها |
| `BankKeeper` | `BankModule` | ماژول مدیریت تراکنش‌های بانکی |
| `VaultKeeper` | `VaultModule` | ماژول مدیریت صندوق (بر اساس استاندارد شبیه به ERC-4626) |
| `AccountKeeper` | `AccountModule` | ماژول مدیریت مشخصات حساب و nonce |
| `MsgServer` | `Runtime dispatch` | ارسال فراخوانی‌ها به ماژول‌های ران‌تایم |
| `message routing` | `match on RuntimeCall` | مسیریابی فراخوانی‌ها با استفاده از پترن مچینگ در Rust |
| `Cache` | `cloned temporary RuntimeState` | کپی موقت وضعیت برای اجرای آزمایشی تراکنش |
| `Commit` | `replace committed state` | جایگزینی وضعیت موقت با وضعیت نهایی در صورت موفقیت |
| `Rollback` | `discard temporary state` | دور انداختن وضعیت موقت در صورت بروز خطا |

## ۲. مقایسه سینتکس (Go vs Rust Syntax)

| موضوع | Go | Rust | توضیحات |
| :--- | :--- | :--- | :--- |
| **تعریف نگاشت** | `map[string]uint64` | `HashMap<String, u64>` | مجموعه کلید و مقدار پویا |
| **آرایه پویا** | `[]Message` | `Vec<RuntimeCall>` | بردار یا لیست پویا در حافظه |
| **مدیریت خطا** | `if err != nil` | `match / Result<T, E> / ?` | سیستم صریح مدیریت خطا با نوع‌های درونی |
| **انتزاع رفتار** | `interface` | `enum` یا `trait` | استفاده از `enum` برای مجموعه‌های بسته و محدود از دستورالعمل‌ها بسیار رایج و کارآمد است |
| **اشاره‌گر و ارجاع** | Pointer / Map reference | `ownership` و `borrowing` | قوانین سخت‌گیرانه زمان کامپایل برای دسترسی امن به حافظه |
| **افزودن به لیست** | `append(results, res)` | `results.push(res)` | درج داده جدید در انتهای بردار |
| **عدم وجود مقدار** | `nil` | `Option<T>` | به جای استفاده از اشاره‌گرهای خالی که ممکن است به خطای زمان اجرا ختم شوند، از ایمنی `Option` استفاده می‌شود |

## ۳. معماری اتمیک و مدیریت حافظه در Rust

در پروژه Go، نگاشت‌ها (maps) به صورت پیش‌فرض مرجع (reference) هستند و برای ایجاد یک حافظه موقت (Cache) نیاز به حلقه‌های عمیق جهت کپی کردن داده‌ها (deep copy) داشتیم.

در **Rust**، پیاده‌سازی متد `Clone` برای `HashMap` به صورت خودکار تمام کلیدها و مقادیر را عمیقاً کپی می‌کند:
```rust
let mut cached_state = self.state.clone();
```
این ویژگی به ما این امکان را می‌دهد که به سادگی معماری اتمیک زیر را پیاده‌سازی کنیم:
۱. از وضعیت متعهد شده اصلی (`self.state`) یک کلون ایجاد می‌کنیم (`cached_state`).
۲. تراکنش را روی این کپی موقت اعتبارسنجی و اجرا می‌کنیم.
۳. در صورت بروز هرگونه خطا در میان مراحل اجرای دستورالعمل‌ها، کل تراکنش لغو شده و وضعیت اصلی بدون تغییر باقی می‌ماند (**Rollback**).
۴. در صورت موفقیت کامل تمامی فراخوانی‌ها، مقدار nonce امضاکننده را اضافه کرده و کپی موقت را به عنوان وضعیت اصلی جدید ذخیره می‌کنیم (**Commit**):
```rust
self.state = cached_state;
```

## ۴. قوانین عاریه و مالکیت (Ownership & Borrowing)

زبان Rust با استفاده از قوانین مالکیت، امنیت حافظه را در زمان کامپایل بدون نیاز به زباله‌روب (Garbage Collector) تضمین می‌کند:
- **مرجع غیرقابل تغییر (`&T`):** به هر تعداد می‌توان از یک داده ارجاع خواندنی ایجاد کرد.
- **مرجع قابل تغییر (`&mut T`):** در هر لحظه تنها یک ارجاع نوشتنی و انحصاری می‌تواند به یک بخش از داده وجود داشته باشد.
- **تضمین عدم تداخل:** ماژول `VaultModule` برای انتقال توکن‌ها به طور انحصاری از `BankModule` در بازه‌های زمانی کوتاه و مشخص استفاده می‌کند. این کار به وسیله طول عمرها و ایجاد بلاک‌های کوچک `{ ... }` جهت پایان دادن به ارجاع‌های نوشتنی پیش از شروع عملیات بعدی صورت می‌گیرد تا از تداخل ارجاع‌های هم‌پوشان جلوگیری شود.

## ۵. نحوه اجرا و بررسی تست‌ها

برای اجرای پروژه و تست‌ها نیاز به نصب بودن کامپایلر Rust دارید.

### اجرای برنامه دمو:
```bash
cargo run
```
این دستور شبیه‌سازی اجرای دو تراکنش ناموفق (که تراکنش به صورت اتمیک لغو می‌شود) و موفق (که موجودی و سهم‌ها به درستی بروزرسانی می‌شوند) را در خروجی نمایش می‌دهد.

### اجرای تست‌های یکپارچه‌سازی:
```bash
cargo test
```
این دستور صحت پیاده‌سازی ماژول‌ها، عدم پذیرش حملات Replay (اعتبارسنجی مجدد nonce)، لغو تراکنش‌های نامعتبر و رفتارهای صندوق را تایید می‌کند.

### بررسی قالب‌بندی کد:
```bash
cargo fmt --check
```
